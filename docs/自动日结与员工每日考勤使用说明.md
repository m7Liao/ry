# 自动日结与员工每日考勤使用说明

更新日期：2026-10-27。沿用当前单体后端、若依 Quartz、MyBatis、JWT 与 H5 移动布局，不新增业务表。

## 1. 本次交付

- 自动日结：按明确场所范围扫描已结束窗口，生成缺失结果、按原快照结算历史待结算结果。
- 任务管理：复用“系统监控 → 定时任务”的启停、立即执行、Cron 和执行日志。
- 失败处理：单员工事务、部分失败可见、临时数据库错误最多尝试3次，后续周期继续处理未完成项。
- 员工 H5：按月份和状态查看本人每日结果，显示上下班记录、异常和工时。

手动计算、批量重算、看板和原始扫码流程继续保留。自动日结不依赖管理员在线，也不创建或模拟管理员登录身份。

## 2. 安装与启用

本机已执行 [attendance-auto-settle.sql](../Vue-springboot3/sql/attendance-auto-settle.sql)。该文件只新增真实日结任务模板，不改写既有结果、不新增表。

模板初始状态为**暂停**，调用目标为 `attendanceDailyTask.settle('')`，Cron 为 `0 0/10 * * * ?`（每10分钟）。空参数不能执行，必须先明确配置范围。

管理员操作：

1. 进入“考勤管理 → 办公场所”，从“场所ID”列查看需要处理的场所编号。
2. 进入“系统监控 → 定时任务”，找到“考勤自动日结（先配置场所范围）”。
3. 修改调用目标，例如 `attendanceDailyTask.settle('1,2')`，其中1、2必须替换为实际场所ID。
4. 保持“不允许并发”和“不触发立即执行”的错过执行策略，保存。
5. 可以先点击“执行一次”，在“任务日志”检查范围、结果与失败原因。
6. 核对后切换为正常 / 启用状态，之后按Cron周期执行。需要停止后续触发时切回暂停。

支持1～100个正整数ID，以逗号分隔，可去重。空值、`*`、`ALL`、0、负数及越界数字会拒绝，不提供隐含的全部场所范围。任务“暂停”不妨碍管理员明确点击“执行一次”，这是现有若依调度行为。

后台服务须持续运行。业务日期和窗口使用 Asia/Shanghai；默认10分钟间隔不依赖钟点时区。若自行修改为每天固定时刻执行，应确认部署时的 JVM / Quartz 时区。

迁移可重复执行；已有 `attendanceDailyTask.settle(...)` 任务时不追加模板，不覆盖用户配置或启停状态。新机器须先安装系统、Quartz、场所员工、扫码、规则、每日结果及看板增量，再执行本文件。自动日结增量不新增表；另安装月报和人脸增量后，完整库为39张表。

## 3. 处理规则与边界

| 项目 | 当前规则 |
|---|---|
| 新建日期范围 | 上海日期的今天、昨天、前天，按先旧后新处理 |
| 新建前提 | 场所和当前规则启用，员工当前绑定该场所，任职日期覆盖目标日，且当天尚无结果 |
| 工作日窗口 | 上下班窗口结束的整分钟全部过去后，才生成最终结果 |
| 夜班 | 等到次日或更后的窗口结束，归属上班当天 |
| 休息日 | 次日零时后生成休息日结果，不在当日提前固定配置 |
| 历史待结算 | 扫描配置场所中所有已结束的 `PENDING`，不限最近3天，使用原快照 |
| 当前规则或场所停用 | 不新增结果；已有且窗口结束的待结算仍按原快照处理 |
| 已结算结果 | 自动任务不改写正常、异常或休息日结果，也不增加其计算次数 |
| 已有结果换绑场所 | 每人每天唯一，不复制或移动历史结果 |
| 单次上限 | 每场所每日最多处理1000名待生成员工，超限报告失败；每场所每次最多结算1000条待结算，剩余后续周期继续 |

例如22:00～次日06:00、下班后可打卡120分钟，次日08:00:59.999仍处于窗口内，08:01起允许结算。没有记录时才据此判定缺卡，未结束的窗口不会被提前判缺。

首次补算仍采用当前人员绑定及当前启用规则，没有历史排班和绑定流水。自动补新只覆盖最近3个班次开始日期，停机更久形成的未生成历史日期需管理员核对后手动补算。已存在的旧待结算快照可自动追补。

源记录、宽限、工时和日期口径与 [每日考勤说明](每日考勤使用说明.md) 一致。多任务或手动操作同时处理同一员工时，沿用员工行锁和唯一索引，不重复保存或把一条打卡分给多个结果。

## 4. 日志、重试与部分失败

任务日志会展示耗时，以及场所数量、新增、结算、跳过、失败和重试次数。跳过为处理项数量，可能包括未结束日期、停用配置或并发下已完成的项，不是缺勤人数。

- 每名员工或每条待结算结果独立事务，失败只回滚该项，已经完成的其他项保留。
- 锁冲突等临时数据访问错误，以及数据访问资源故障最多尝试3次，每次使用新的事务。
- 参数错误、范围错误和业务校验错误不做无意义的即时重试；修复后可“执行一次”或等待下个周期。
- 只要有一项失败，整次任务日志标记失败，并保留已完成数量和首个失败位置。
- 下一次扫描跳过已存在 / 已结算的项，继续处理仍未生成或仍待结算的项。

结果的计算人字段为固定系统标记 `attendanceDailyTask`。手动操作仍记录实际登录账号。普通 void 任务维持原行为；此次调度增加的是可选 `TaskExecutionResult` 摘要，异常日志保留被调用方法的真实原因。

暂停或删除任务用于停止后续调度，不等于回滚已生成的结果，也不承诺强制中断已经开始的执行。原有手动补算和按快照重算可以继续使用。

## 5. 权限与架构

任务配置和触发使用现有 `monitor:job:*`，日志使用现有任务日志权限。这些是全局运维能力，应由负责调度的管理员管理，不能把任务执行范围等同于某次登录请求的部门范围。

自动入口没有HTTP接口，只提供白名单中的 `attendanceDailyTask.settle(String)`。框架白名单只补充 `com.ruoyi.attendance.task` 包，原有调用限制保留；参数再次限定为明确的场所ID。

```text
Quartz 调度 / 立即执行
    → AttendanceDailyTask
        → AttAutoSettleService（范围、扫描、重试、摘要）
            → AttDailyWorker（单项事务、快照和共用计算）
                → AttDailyCalculator / MyBatis

手动 Controller → 原权限和数据范围 → AttDailyServiceImpl → 同一个 Worker
```

人工批量重算仍在外层事务内完成，任一越权或失败整批回滚。自动执行不调用需要登录身份的手动入口。

## 6. 员工 H5 每日结果

地址为 `/h5/daily`。员工可从签到页或原始记录页点击“我的每日考勤”，未登录时进入现有 H5 登录，登录后返回原页。

1. 使用已绑定员工档案的本人系统账号登录。
2. 选择月份及全部 / 正常 / 异常 / 待结算 / 休息日状态，点击“查询 / 刷新”。
3. 查看该日场所、计划班次、实际打卡、异常、计划工时、计算工时和更新时间。
4. 每页10条，点击“加载更多”继续；原始签到仍可从导航进入。

员工复用 `attendance:checkin:submit` 权限，无需管理端每日列表或看板权限。服务端始终从当前 JWT 取得账号，忽略冒填的用户、员工和数据范围。账号实时停用后，即使旧Token仍存在，也不能继续查询。

只返回本人结果所需字段，不返回其他账号、部门ID、内部规则JSON或计算人。员工调部门、换场所后仍可查看自己的既有结果；离职档案仍可查历史，账号或所属部门停用的处理与原 H5 本人记录一致。

未生成结果不表示缺勤。待结算工时显示“待结算”，缺卡工时显示“待确认”。对结果有疑问时联系管理员核对，本版没有员工自助修改或补签。

接口为 `GET /attendance/checkin/daily`，支持 `beginDate/endDate/resultStatus/pageNum/pageSize`，日期为 `yyyy-MM-dd`。均不传日期时默认最近30天，提供日期时需成对、按先后排列且不超过93天。返回若依分页 `rows/total/code/msg`，身份校验在分页前执行。
