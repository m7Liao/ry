# 办公场所管理与员工档案使用说明

更新日期：2026-10-26。适用于当前 `ruoyi-attendance` 业务模块。

## 1. 本次实现范围

菜单入口为“考勤管理 → 办公场所”和“考勤管理 → 员工档案”。支持分页查询、筛选、详情、新增、修改、批量删除，以及员工主要办公场所的绑定和更换。

当前业务关系：

```text
系统部门 ── 管理办公场所
    │             │
系统账号 ── 员工档案 ── 绑定一个主要办公场所
    │
    └─ 员工所属部门实时取账号当前部门
```

- 每份员工档案必须关联一个已存在的系统账号；一个账号最多关联一份档案。
- 每份档案必须绑定一个主要办公场所。本版没有多场所绑定表。
- 员工工号、场所编码分别全局唯一，数据库默认排序规则下不区分大小写。
- 员工真实姓名、业务联系电话和邮箱单独保存，不反向覆盖账号昵称和联系方式。
- 员工档案创建后不能更换关联账号，防止后续签到身份混淆。
- 本版不包含公司独立档案、第三方地图选点、二维码、签到、人脸识别和统计看板。

## 3. 推荐录入顺序

1. 在“系统管理 → 部门管理”建立组织部门。
2. 在“系统管理 → 用户管理”建立员工账号并设置部门。
3. 在“考勤管理 → 办公场所”登记办公地址和管理部门。
4. 在“考勤管理 → 员工档案”选择账号，填写工号、姓名和入职日期，选择主要办公场所后保存。
5. 检查员工列表的账号、部门和场所，以及场所列表中的绑定人数。
6. 为实际管理人员配置角色和数据范围，再用普通账号验证可见数据。

## 4. 办公场所操作

### 4.1 新增与修改

| 字段 | 规则 |
|---|---|
| 场所编码 | 必填，最长32字符，只能使用字母、数字、下划线和短横线；例如 `HQ_001` |
| 场所名称 | 必填，最长100字符 |
| 管理部门 | 必填，必须是可管理、未删除且启用的部门，用于部门数据权限 |
| 详细地址 | 必填，最长255字符 |
| 经度、纬度 | 可同时留空；填写时必须成对，经度 -180～180，纬度 -90～90，最多6位小数 |
| 坐标系 | `GCJ02`、`WGS84`、`BD09` 三选一，默认 `GCJ02` |
| 联系人、联系电话 | 可选，分别最长50、30字符；电话允许数字、空格、`+`、括号和短横线 |
| 状态 | 启用或停用 |
| 备注 | 可选，最长500字符 |

“修改”会完整保存本页字段；API 调用方也应提交完整业务字段。坐标清空时，经纬度应同时发送 `null`。

坐标只保存数值和坐标系，不自动定位、选点或转换。留空的场所可用于档案绑定，未来接入定位签到时应另行要求有效坐标并定义距离规则。

### 4.2 筛选、状态与绑定人数

可按编码、名称、管理部门和状态查询。绑定人数统计当前关联此场所的全部档案，包括离职员工；它不是实时在场人数。

停用场所后，已有档案保留绑定关系，允许继续维护其联系方式、离职状态等内容；不能把其他员工新增或换绑到该停用场所。员工页的场所选择器会标记停用项，现有绑定可保留。

### 4.3 删除

有任何员工档案关联时禁止删除，即使员工已离职也一样。先换绑或处理员工档案，才能删除场所。支持批量删除，每次最多100条；同一批中有记录不可删除时，整批回滚。

场所是历史业务的基础资料，实际运营通常建议停用并保留。后续接入考勤记录时，还需扩展历史引用和删除规则。

## 5. 员工档案与绑定操作

### 5.1 新增档案

| 字段 | 规则 |
|---|---|
| 工号 | 必填、全局唯一，最长32字符，允许字母、数字、下划线和短横线 |
| 员工姓名 | 必填，最长50字符 |
| 系统账号 | 必填；只可选择数据范围内、账号和部门均启用、尚未绑定档案的账号 |
| 所属部门 | 从系统账号读取；此页不能修改，调整部门请到用户管理 |
| 办公场所 | 必填，选择有数据权限且启用的场所 |
| 联系电话、邮箱 | 可选，最长30、100字符，服务端验证格式 |
| 入职日期 | 必填，不能晚于今天 |
| 员工状态 | 在职、离职 |
| 离职日期 | 离职时必填，不能早于入职日期或晚于今天；在职时必须为空 |
| 备注 | 可选，最长500字符 |

账号、场所下拉框每次最多返回100条匹配结果，数据较多时输入名称搜索。账号选择接口只返回选择所需字段，不包含密码散列、角色列表等系统用户信息。

### 5.2 修改与换绑

点击“修改 / 绑定”，在“办公场所”中选择新的启用场所并保存。换绑后，两个场所的绑定人数随查询自动更新。

员工部门随账号当前部门变化，不另外复制保存。账号调整部门后，员工档案的数据范围也随之变化。办公场所的管理部门独立维护，员工部门改变不会自动移动场所或变更绑定。

### 5.3 离职与账号停用

将状态改为“离职”并填写离职日期。档案状态和登录账号状态分别维护：本页标为离职不会自动禁用账号。若需要禁止登录，请在用户管理停用账号，并按现有在线用户功能处理登录会话。

### 5.4 删除与解除绑定

删除档案会解除账号和场所绑定，系统账号保留，可再次创建档案。删除操作不提供回收站，应慎用。离职通常应保留档案并修改状态。

账号有关联档案时，系统用户删除操作会被拦截。场所有关联时，管理部门删除操作也会被拦截。检查在系统业务删除事务内同步执行，业务模块通过公共删除事件接入，系统模块不反向依赖考勤模块。

## 6. 角色与数据权限

初始化迁移只为管理员角色补充新菜单，不给普通角色自动开权限。在“系统管理 → 角色管理”中选择需要授权的角色，勾选“考勤管理”和对应页面、操作项。

| 权限前缀 | 操作 |
|---|---|
| `attendance:site:` | `list`、`query`、`add`、`edit`、`remove` |
| `attendance:employee:` | `list`、`query`、`add`、`edit`、`remove` |

`list` 控制列表，`query` 控制详情按钮，`edit` 同时允许读取编辑所需详情。只有查看权限的用户不能保存。新增和修改所需的部门、账号、场所选项接口使用业务权限，不要求管理人员额外取得系统用户管理权限。

数据范围复用若依角色配置：全部数据、自定义部门、本部门、本部门及以下、仅本人。场所按管理部门过滤；员工按关联账号部门过滤，“仅本人”则只显示本人账号的档案。场所没有“本人”字段，因此仅本人数据范围不能管理场所。

数据权限也作用于详情、修改、删除、选择器和新绑定目标。直接在接口中更换记录ID或提交范围外部门、场所，不能绕过检查。对于当前员工已有的场所绑定，允许保留原绑定以维护档案。

调整角色及数据范围后，使用重新登录的会话验证效果。角色变更影响登录缓存的具体行为仍遵循框架实现，不假定所有数据范围变更都能立即刷新在线会话。

## 7. 开发与接口索引

后端路径：[ruoyi-attendance](../Vue-springboot3/ruoyi-attendance)。Controller、领域实体、Service 和 Mapper 在同一模块中；模块依赖 `ruoyi-system`，由 `ruoyi-admin` 引入。前端页面位于 `src/views/attendance/`，接口函数位于 `src/api/attendance/`。

| 方法与地址 | 作用 |
|---|---|
| `GET /attendance/site/list` | 场所分页查询，参数 `pageNum/pageSize/siteCode/siteName/deptId/status` |
| `GET /attendance/site/{id}` | 场所详情 |
| `POST /attendance/site` | 新增场所 |
| `PUT /attendance/site` | 修改场所，请提交 `siteId` 和完整业务字段 |
| `DELETE /attendance/site/{ids}` | 删除场所，多ID逗号分隔 |
| `GET /attendance/site/departments` | 数据范围内的启用部门 |
| `GET /attendance/site/options?keyword=名称` | 场所选项，最多100条 |
| `GET /attendance/employee/list` | 员工分页查询，参数 `pageNum/pageSize/employeeNo/employeeName/deptId/siteId/status` |
| `GET /attendance/employee/{id}` | 员工详情 |
| `POST /attendance/employee` | 新增档案并绑定 |
| `PUT /attendance/employee` | 修改档案或换绑，请提交 `employeeId` 和完整业务字段 |
| `DELETE /attendance/employee/{ids}` | 删除档案并解除绑定 |
| `GET /attendance/employee/users?keyword=账号或昵称` | 未绑定的启用账号选项，最多100条 |

所有接口要求登录，使用框架既有 `Authorization: Bearer ...`。前端请求经 `/dev-api` 代理。列表返回 `rows/total/code/msg`，其他查询返回 `data/code/msg`。授权失败使用业务响应码403，参数和业务校验失败通常为500；HTTP状态成功不代表业务成功。

业务表：`att_site`、`att_employee`。数据库唯一索引防止并发重复编码或绑定，外键保护关联；业务校验补充停用、日期和逻辑删除规则。新增、修改、删除记录到若依操作日志。
