# 人脸核验签到使用说明

更新日期：2026-10-27。当前已接入本机提供的虹软 ArcFace Java Windows x64 V3.0 SDK，使用现有若依账号、员工绑定、角色权限、MyBatis、事务和H5布局。月度统计见 [员工月度汇总说明](员工月度出勤与工时汇总使用说明.md)。

## 1. 本次完成与使用边界

已完成真实SDK加载、激活、初始化、单人脸检测、特征提取、本人1:1比对、员工档案管理、签到保存和核验摘要。成功签到继续进入既有每日计算、自动日结、看板和月报，不另建考勤计算体系。

本版未启用活体检测、人证核验、年龄/性别属性、质量评分、视频跟踪、Face-api或人脸库1:N搜索。单张图片比对不能证明真人在场，也不能据此声称已经防住照片代打卡。课程中这些能力仍应单独列状态。

## 2. 管理员录入员工人脸

1. 在用户管理建立账号，在员工档案绑定账号及办公场所。
2. 进入“考勤管理 → 员工档案”，点击对应员工的“人脸档案”。
3. 查看引擎是否就绪及是否已经录入。
4. 打开摄像头拍照，或选择经过本人同意的正脸JPEG/PNG图片。
5. 勾选已说明用途并取得采集同意，点击保存；已有档案时会再次确认替换。
6. 需要撤销时点击“撤销人脸”。撤销后，启用人脸核验的签到要求该员工重新录入。

每名员工保留一份当前特征。替换增加当前档案版本；撤销后重新录入从版本1开始，版本号不是全局唯一模板编号，也不提供历史特征恢复。已有签到的核验摘要独立保留，不因撤销而删除。

管理角色需要员工档案菜单，以及 `attendance:face:query`、`attendance:face:enroll`、`attendance:face:remove` 中相应权限；员工的部门数据范围同时生效。录入、替换和撤销有系统操作日志，原图和特征不会写入请求/响应审计正文。

员工没有自行上传替换档案的接口；普通签到权限不能取得管理端人脸特征或核验摘要。

## 3. 员工签到

1. 员工扫描场所动态二维码，并用已绑定的本人账号登录。
2. 系统校验账号、部门、员工状态、场所绑定、二维码和场次。
3. 启用人脸时，页面展示本人录入状态；用摄像头拍照后点击“核验人脸并签到”。
4. 后端只取当前账号对应员工的加密特征，调用虹软进行检测、提取和比对。
5. 得分不低于服务端阈值，且二维码、场次仍有效时，原始签到与核验摘要在同一事务提交。

服务器不接受客户端传入的“核验通过”、分数、阈值、员工身份或特征来代替识别。启用人脸后，普通 `/submit` 接口无法新增普通扫码记录；已有的同员工同场次记录仍按原有幂等规则返回。

一次只允许一张人脸。未检测到人脸、多脸、比对失败、未录入、档案版本不兼容、失效二维码、场次关闭及账号失效均会拒绝。识别耗时不会延长二维码有效期，保存前会再次检查。

图片限制为JPEG/PNG、不超过4MB，至少80×80，单边不超过4096且不超过800万像素。服务端在完整解码前检查尺寸，并统一为最长边不超过1280、宽度为4的倍数的BGR24数据。

## 4. 查看核验结果

管理端“签到记录”中，新增成功记录的方式显示“扫码＋人脸核验”。详情显示虹软分数、当次阈值及档案版本；原有普通扫码记录继续显示扫码。

成功核验摘要以原始记录ID唯一关联，保存模型标识、分数、阈值、档案版本及核验时间；不保存采集照片或明文特征。失败核验不会生成考勤记录。本版没有失败尝试业务报表。

## 5. 本机配置与迁移

本机已安装 [attendance-face.sql](../Vue-springboot3/sql/attendance-face.sql)，新增：

- `att_employee_face`：员工ID唯一的加密特征档案。
- `att_face_verification`：签到记录ID唯一的成功核验摘要。

同时为原始签到方式约束增加 `QR_FACE`，补充管理员权限，不改写旧签到和每日结果。完整安装含月报与人脸增量后为39张表，其中8张考勤业务表。脚本可重复执行，不清空数据；已有同名表的其他结构差异需单独迁移。

SDK放置在 `.runtime/arcsoft/windows-x64/ArcSoft_ArcFace_Java_Windows_x64_V3.0/`，保留完整包结构。JAR和DLL不进入源码仓库，也不会打入应用JAR；通过运行时适配加载实际供应商接口。

本机配置文件为 `.runtime/arcsoft/face-local.yml`，启动脚本已将它作为可选配置加载。示例仅列字段，不包含真实密钥：

```yaml
attendance:
  face:
    enabled: true
    app-id: "由本机配置提供"
    sdk-key: "同一应用的Windows Java SDK_KEY"
    sdk-jar: "../.runtime/arcsoft/windows-x64/ArcSoft_ArcFace_Java_Windows_x64_V3.0/libs/arcsoft-sdk-face-3.0.0.0.jar"
    native-dir: "../.runtime/arcsoft/windows-x64/ArcSoft_ArcFace_Java_Windows_x64_V3.0/libs/WIN64"
    threshold: 0.80
    encryption-key: "32字节随机密钥的Base64"
```

相对路径以当前后端工作目录为基准。本机SDK、应用标识和加密密钥已经配置，人脸要求已启用；真实员工仍需管理员先行录入。配置修改后须重启后端。阈值0.80是当前实施值，真实环境应使用经过同意的样本评估，不能以少量示例分数认定准确率。

首次激活需连通虹软官方服务；已验证Java17 x64能加载本机这套SDK。SDK错误码94209在本次首次受限网络下出现，允许官方激活网络访问后激活成功。其他版本、操作系统、授权有效期及运行依赖应以对应下载包为准，不能直接把本机Windows DLL复制成Linux部署方案。

`.runtime/`及后端根目录的 `ArcFace*.dat` 已被Git忽略。特征使用AES-256-GCM、随机nonce和员工ID附加认证数据加密；篡改或跨员工复制密文会失败。数据库恢复须配套原加密密钥，丢失密钥后需要重新录入。密钥不返回前端。

`enabled: false` 时使用原普通扫码流程；启用后引擎或密钥异常会阻止新增签到，不自动放行。请在正式演示前核对所有参与员工的档案。

## 6. 摄像头与手机环境

浏览器摄像头需要安全上下文：本机可用 `http://localhost`，手机通过局域网IP访问通常需要受信任的HTTPS。仅运行 `start-dev.ps1 -Lan` 不会自动解决手机摄像头权限。

当前启动脚本仍用于开发服务，没有因此完成公网HTTPS部署。建议先在本机浏览器验证摄像头，再在已配置HTTPS的演示环境进行手机扫码验收。权限拒绝、设备占用、视频尚未就绪会显示提示；拍照、关闭或离开页面后停止摄像头并释放预览URL。

```powershell
# 普通边界，无需启动服务或激活SDK

# 真实SDK检查，使用经过同意的本地示例路径
powershell.exe -NoProfile -ExecutionPolicy Bypass -File test/verify-face-unit.ps1 -Native `
  -Portrait '本地正脸图.png' -DifferentPortrait '另一张不同人脸图.png' -MultiplePortrait '多脸图.png'
```
