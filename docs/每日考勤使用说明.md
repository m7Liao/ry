# 每日考勤计算与结果查询

更新日期：2026-10-27。适用于当前 `ruoyi-attendance` 单体业务模块。

## 1. 使用入口与流程

菜单为“考勤管理 → 每日考勤结果”，规则列表也有“每日结果”快捷入口。

```text
场所规则 + 员工绑定 + 原始签到记录
                 ↓
选择一个场所、一个考勤日期 → 手动计算
                 ↓
首次保存身份 / 场所 / 规则快照 → 展示每日结果
                 ↓
窗口结束或签到数据变化 → 按原快照重算
```

现有扫码提交仍以场次有效期、员工身份与绑定为准；每日计算从原始记录中匹配上下班，不修改原始记录。同一员工同一场次只能签到一次，现阶段请分别创建上班和下班签到场次。

## 2. 首次计算

1. 建立员工档案，绑定办公场所，配置并启用该场所的固定班次规则。
2. 按现场需要建立上下班场次，员工分别扫码确认签到。
3. 进入每日结果页面，点击“手动计算”，选择场所、考勤日期。
4. 核对提示后计算。页面显示新增和已有结果跳过数量。
5. 按日期、员工、场所、结果状态或异常类型查询；点击“详情”查看来源记录编号和首次规则快照。

计算后可到 [考勤看板](考勤看板使用说明.md) 查看趋势和场所对比。看板的已结算、缺卡和类型分布与列表通过明确条件联动；列表新增“统计范围”筛选，用于只看已结算或已结算缺卡。

一次处理一个场所、一天，最多1000名数据范围内的员工。不支持未来日期。场所必须在操作者管理范围内，并有启用规则。

**历史日期首次计算使用当前启用规则和当前绑定员工**，没有历史排班、调岗或场所绑定流水。员工必须满足入职日期不晚于考勤日期、离职日期为空或不早于考勤日期；离职当天包含在内。账号停用不会自动抹去其历史应考勤资格。首次补算前须确认当前人员和规则是否适用于该日期。

只处理当前账号有权管理的员工。即使一个场所绑定了其他部门员工，本部门管理员也不能替范围外员工生成结果。数据范围内没有符合条件的员工时返回新增0条。

重复点击首次计算只跳过已有结果，不覆盖快照或更新结果。已有结果的员工换绑其他场所后，再对同一天计算也不会创建第二条结果。

## 3. FIXED_V1 计算口径

| 项目 | 规则 |
|---|---|
| 日期与时区 | 使用 Asia/Shanghai；跨天班次归属上班当天 |
| 工作日 | 按首次保存的每周星期判断，暂不含法定节假日、调班日历 |
| 上班记录 | 同一员工、同一场所、上班窗口内最早记录；同一时刻取较小记录ID |
| 下班记录 | 同一员工、同一场所、下班窗口内最晚记录；同一时刻取较大记录ID |
| 窗口范围 | 包含开始与结束时刻所在整分钟，如结束10:00，10:00:59.999仍可匹配，10:01起不匹配 |
| 当前时间 | 不读取晚于本次计算时刻的打卡 |
| 迟到 | 打卡按分钟取整，超过“上班时间＋宽限”才算；异常分钟为相对计划上班的完整差值 |
| 早退 | 打卡按分钟取整，早于“下班时间－宽限”才算；异常分钟为相对计划下班的完整差值 |
| 缺卡 | 对应窗口结束分钟全部过去后仍无匹配，才标记缺卡 |
| 工时 | 两次有效打卡的分钟时间差减固定休息时长，下限0；任一缺卡则为待确认 |
| 未结束班次 | 状态待结算，工时不提前结算；已关闭的上班窗口可先显示上班缺卡 |
| 非工作日 | 休息日、计划及计算工时均为0，不标记缺卡，不核算加班 |
| 记录分配 | 一条原始记录不能同时作为其他每日结果的上班或下班记录 |

例如上班09:00、宽限5分钟：09:05:59不算迟到，09:06算迟到6分钟。下班18:00、早退宽限5分钟：17:55不算早退，17:54算早退6分钟。

普通班次09:00～18:00，休息60分钟，08:59与18:10打卡，计划工时480分钟，签到区间计算工时491分钟。这里的工时按区间计算，尚未扣除中途离岗，也不单独识别或审批加班，不能直接作为工资或加班结算依据。

夜班22:00～次日06:00、休息30分钟，22:10与次日05:58打卡，计划工时450分钟，计算工时438分钟。次日签到仍属于前一天班次。

计算会拒绝同一套规则下相邻工作日的打卡窗口重叠，避免班次归属不明确。规则调整造成不同日期快照的窗口重叠时，已分配给其他结果的打卡不会再次占用，需核对异常并另行制定更正方案。

## 4. 结果状态和查询

| 状态 | 含义 |
|---|---|
| 待结算 `PENDING` | 工作日且至少一个打卡窗口尚未结束；需后续重算 |
| 休息日 `REST` | 快照规则下的非工作日 |
| 正常 `NORMAL` | 两个窗口结束，两次记录有效，没有迟到早退 |
| 异常 `ABNORMAL` | 两个窗口结束，存在迟到、早退或任一缺卡 |

异常标签可以并存，如同一天同时迟到、早退。双缺卡保留两个缺卡标记，不自动认定旷工或扣薪。

列表支持考勤日期范围、工号、姓名、场所、状态、异常类型筛选。详情显示：身份与场所快照、计划时间、上下班窗口、匹配记录的原始时间和编号、异常分钟、计划与计算工时、计算次数和计算人，以及初次保存的规则参数与算法版本。

## 5. 按快照重新计算

窗口结束后不会自动刷新为最终状态，须点击单条“按快照重算”，或勾选记录后批量操作。每次最多100条。

- 重算重新读取该员工在原场所、原窗口的可用签到记录。
- 使用首次保存的 `FIXED_V1` 规则快照，不采用当前规则的新值或停用状态。
- 员工改名、调部门、换场所或规则修改，不覆盖结果中的身份、部门、场所和规则快照。
- 更新匹配记录、状态、异常分钟、工时、计算时间和计算人，并增加计算次数。
- 一个批次中有任何记录越权或处理失败时，整个批次回滚。
- 计算和重算按员工串行、结果按固定顺序加锁，防止同一记录被并发占用于不同日期。

本版没有“套用最新规则覆盖历史”的按钮、每日结果删除接口或补签入口。确需更正适用规则时，应另行设计有审计的更正与历史版本机制。普通规则编辑的 `version` 仍是并发控制计数，结果快照另行保存。

## 6. 权限与删除保护

| 权限 | 用途 |
|---|---|
| `attendance:daily:list` | 结果列表与场所筛选选项 |
| `attendance:daily:query` | 详情、来源编号及规则快照 |
| `attendance:daily:calculate` | 按场所和日期首次计算，以及场所选项 |
| `attendance:daily:recalculate` | 按结果原快照重新计算 |

迁移只为管理员补充权限，普通角色需由管理员授权，重新登录后验证。只读人员无需获得场所、员工、规则编辑权限。

管理端每日结果按首次计算保存的员工部门ID应用若依部门数据范围；仅本人按结果账号ID过滤。首次计算还会检查场所管理范围和员工当前部门范围。员工后来调部门，不会把旧结果自动转到新部门。

存在每日结果时，关联员工档案和规则不可删除，建议离职或停用并保留。场所通过原有员工、规则、场次和数据库外键继续受保护。原始签到记录通过来源外键保留，系统没有提供对其任意删除的业务接口。

## 7. 安装与架构

本机已执行 [attendance-daily.sql](../Vue-springboot3/sql/attendance-daily.sql)。已有基础数据、扫码和规则模块的库，只需执行本次增量。可重复执行，不清空业务数据；既有同名表的结构升级需另行迁移。

完整空库顺序：

```sql
SOURCE ry_20260417.sql;
SOURCE quartz.sql;
SOURCE attendance-base.sql;
SOURCE attendance-checkin.sql;
SOURCE attendance-rule.sql;
SOURCE attendance-daily.sql;
SOURCE attendance-dashboard.sql;
```

前两份会重建表，不能用于已有库日常升级。完整初始化共37张表，其中6张考勤业务表；最后一份只补充看板菜单。`att_daily_result` 以 `(employee_id, attendance_date)` 唯一键防止重复，保存首次规则 JSON 与算法版本，保留原始打卡来源外键。

后端仍在 `ruoyi-attendance` 内：

```text
AttDailyController
    → IAttDailyService / AttDailyServiceImpl
        → AttDailyCalculator（固定口径纯计算）
        → AttDailyMapper / AttDailyMapper.xml
```

复用 Spring Security、JWT、`@PreAuthorize`、`@DataScope`、MyBatis、事务及若依操作日志，未新增微服务和前端依赖。前端为 `src/views/attendance/daily/index.vue` 与 `src/api/attendance/daily.js`。

| 方法与后端路径 | 用途 |
|---|---|
| `GET /attendance/daily/list` | 分页查询，支持 `beginDate/endDate/attendanceDate/siteId/employeeNo/employeeName/resultStatus/abnormalType/resultGroup`；`resultGroup` 为 `SETTLED` 或 `MISSING` |
| `GET /attendance/daily/{id}` | 有权限的结果详情，包含结构化 `ruleConfig` |
| `POST /attendance/daily/calculate` | `{ "siteId": 1, "attendanceDate": "2026-10-19" }`，返回 `created/skipped/candidates` |
| `POST /attendance/daily/recalculate` | `{ "resultIds": [1, 2] }`，返回重算条数 |

使用原有 Bearer Token 和 `/dev-api` 开发代理。日期为有效 `yyyy-MM-dd`，开始不能晚于结束；异常类型为 `LATE/EARLY/MISSING_IN/MISSING_OUT`。不能以 HTTP 200 代替业务成功判断。

固定时钟边界测试不连接数据库，后端打包会编译测试类，再从根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./test/verify-daily-calculator.ps1
```

它通过 Spring Boot 包中的依赖运行测试入口，不启动服务，不增加 JUnit 等依赖。覆盖15项边界，包括分钟宽限、窗口含结束分钟、缺卡、待结算、夜班、休息日、未来记录、同刻记录排序和相邻窗口重叠。

真实接口专项脚本为 [verify-daily.ps1](../test/verify-daily.ps1)。先启动服务，然后执行：

```powershell
$env:ATTENDANCE_TEST_MYSQL_PASSWORD = Read-Host '本地测试库 MySQL root 密码'
try {
    powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./test/verify-daily.ps1
} finally {
    Remove-Item Env:ATTENDANCE_TEST_MYSQL_PASSWORD
}
```

管理员初始化密码已修改时，传入 `-AdminUser/-AdminPassword`；也支持 `-BaseUrl/-RedisCli/-MySqlCli`。仅用于本地 `ry-vue` 开发库：通过接口创建随机前缀的隔离人员与规则，通过测试 SQL 注入历史打卡，最后按本次场所 / 场次ID及随机前缀清理每日结果、打卡和基础数据。产品接口始终不允许客户端自填签到时间。
