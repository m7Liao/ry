# 简单考勤规则配置使用说明

更新日期：2026-10-27。适用于当前 `ruoyi-attendance` 固定班次配置模块。

## 1. 实现范围

菜单入口为“考勤管理 → 考勤规则配置”，也可从办公场所列表点击“考勤规则”。支持按名称、场所、状态筛选，分页查询，详情、新增、修改、启用 / 停用和删除。

采用一个办公场所一套规则的简单模型，不增加员工排班和规则分配表。场所与员工已有绑定关系可供后续计算使用。规则保存于 MySQL，工作日、时间窗口和计划工时可预览。

**规则已接入每日考勤的手动计算**，可按窗口匹配记录并计算迟到、早退、缺卡和工时，详见 [每日考勤说明](每日考勤使用说明.md)。扫码签到仍按原场次有效时间和身份绑定校验，不按规则拦截打卡。修改配置不会改写原始签到记录或已有结果的规则快照。

本版不包含法定节假日自动导入、指定日期调班、轮班、弹性班次、一天多班次、请假和加班。[自动日结](自动日结与员工每日考勤使用说明.md) 已复用当前规则与计算口径，模板需配置范围后启用。缺卡没有单独的可配置公式，按对应窗口结束后是否存在匹配记录判定。

## 2. 录入方式与默认值

1. 先创建启用的办公场所。
2. 进入规则列表，点击“新增规则”。
3. 选择场所，填写名称、工作日、上下班时间和分钟参数。
4. 核对底部预览的上下班打卡窗口与计划工时，点击“保存”。
5. 再次打开详情，确认配置已保存。调整时使用“修改”；规则所属场所不能更换。

新增表单提供以下默认值，但不会自动向数据库插入业务规则：

| 字段 | 默认值 | 可配置范围与说明 |
|---|---|---|
| 规则名称 | 空，必填 | 最长100字符 |
| 每周工作日 | 周一至周五 | 至少一天；周一至周日对应1至7，不能重复 |
| 上班时间 | 09:00 | 24小时制，精确到分钟 |
| 下班时间 | 18:00 | 24小时制，精确到分钟 |
| 下班日期 | 当天 | 当天或次日，跨天必须明确选择次日 |
| 迟到宽限 | 5分钟 | 0～180分钟，不得超过“上班后可打卡” |
| 早退宽限 | 0分钟 | 0～180分钟，不得超过“下班前可打卡” |
| 上班前可打卡 | 60分钟 | 0～360分钟 |
| 上班后可打卡 | 60分钟 | 0～360分钟 |
| 下班前可打卡 | 60分钟 | 0～360分钟 |
| 下班后可打卡 | 120分钟 | 0～360分钟 |
| 固定休息时长 | 60分钟 | 0～720分钟，必须小于班次时长 |
| 规则状态 | 启用 | 首次计算要求启用；按快照重算不受当前停用状态影响 |
| 备注 | 空 | 最长500字符 |

校验在前后端执行，服务端是最终依据。班次时长必须大于0、不超过24小时；上班与下班打卡窗口不能重叠或相接。每个场所仅一套配置，停用配置仍占用该场所，不能再新增第二套，应修改原配置。

## 3. 预览与跨天示例

普通班次09:00～18:00，休息60分钟，计划工时为：

```text
班次时长 = 18:00 - 09:00 = 540分钟
计划工时 = 540 - 60 = 480分钟，即8小时
上班打卡窗口 = 当日08:00～当日10:00
下班打卡窗口 = 当日17:00～当日20:00
```

夜班22:00～次日06:00，休息30分钟，其他窗口参数保持默认：

```text
班次时长 = 8小时
计划工时 = 480 - 30 = 450分钟，即7小时30分钟
上班打卡窗口 = 当日21:00～当日23:00
下班打卡窗口 = 次日05:00～次日08:00
```

窗口以班次上班当天为参照，会显示“前一日 / 当日 / 次日 / 后两日”。例如00:30上班、允许提前60分钟，对应窗口开始为前一日23:30。

工作日按上班当天的星期理解：勾选周一的22:00～次日06:00，表示周一晚上开始、周二早晨结束的班次。工作日配置不等于节假日日历，本版不会自动排除法定节假日。

计划工时仅为时间差减固定休息时长。每日计算采用上班窗口最早、下班窗口最晚记录；宽限内不算异常，超过后按完整差值记录异常分钟，缺卡时工时待确认。跨天结果按上班当天归属，完整口径见每日考勤说明。

## 4. 修改、停用与删除

- 修改已有规则时必须提交最新 `version`。两人打开同一版本时，只允许其中一次保存成功，另一人需重新打开，避免静默覆盖。
- `version` 是并发控制计数，不是完整的规则历史表；每日结果首次计算会另存所用规则快照。
- 已有配置不能换绑场所。确需配置另一个场所时，应新建该场所对应规则。
- 停用的场所不能新增规则，已有规则可继续维护或停用。
- 规则存在时禁止删除对应场所；可先删除规则，或保留场所并停用。
- 已有每日结果的规则不能删除，建议停用保留。没有每日结果时可删除配置，不删除签到场次或原始记录。本版没有规则回收站。

每日结果已有规则快照与显式重算机制，修改规则不会无提示覆盖已有结果。规则生效日期和完整历史排班尚未实现，首次补算历史日期前要确认当前规则是否适用。

## 5. 权限

迁移仅为管理员角色补充菜单，不自动给普通角色授权。在角色管理中勾选“考勤规则配置”及所需操作：

| 权限 | 用途 |
|---|---|
| `attendance:rule:list` | 分页列表与筛选所需场所选项 |
| `attendance:rule:query` | 详情 |
| `attendance:rule:add` | 新增与场所选项 |
| `attendance:rule:edit` | 读取修改详情、保存及场所选项 |
| `attendance:rule:remove` | 删除 |

数据范围复用若依角色配置，按办公场所**当前管理部门**过滤，并作用于详情、新增目标、修改、删除和下拉选项。场所管理部门调整后，规则的可见范围随之调整。规则没有“本人”字段，仅本人数据范围不能管理场所规则。普通员工 H5 签到不需要这些管理权限。

## 6. 迁移、接口与源码

本机已执行 [attendance-rule.sql](../Vue-springboot3/sql/attendance-rule.sql)。其他已有基础模块的环境执行该增量文件即可；它要求先安装 `attendance-base.sql`，不清空现有数据，可重复执行，不自动升级结构不同的既有同名表。

完整空库初始化按顺序执行：

```sql
SOURCE ry_20260417.sql;
SOURCE quartz.sql;
SOURCE attendance-base.sql;
SOURCE attendance-checkin.sql;
SOURCE attendance-rule.sql;
SOURCE attendance-daily.sql;
SOURCE attendance-dashboard.sql;
SOURCE attendance-auto-settle.sql;
SOURCE attendance-monthly.sql;
SOURCE attendance-face.sql;
```

前两份是重建脚本，不得用于已有业务库日常升级。完整初始化共39张表，其中8张考勤表。`att_rule` 以 `site_id` 唯一索引和外键保护场所关联；每日增量建立结果表，看板、日结和月报补菜单或任务，人脸增量新增两表并扩展签到方式。

| 方法与后端路径 | 用途 |
|---|---|
| `GET /attendance/rule/list` | `pageNum/pageSize/ruleName/siteId/status` 筛选 |
| `GET /attendance/rule/{id}` | 带数据权限的详情 |
| `POST /attendance/rule` | 新增完整配置 |
| `PUT /attendance/rule` | 修改完整配置，必须带 `ruleId/siteId/version` |
| `DELETE /attendance/rule/{id}` | 删除单条配置 |

请求沿用 Bearer JWT，前端开发代理前缀为 `/dev-api`。字段名对应实体驼峰属性；`workDays` 为逗号分隔字符串，如 `1,2,3,4,5`；时间为 `HH:mm`；`endNextDay/status` 为字符串 `0` 或 `1`。列表为 `rows/total/code/msg`，详情为 `data/code/msg`，增删改返回 `code/msg`；HTTP 200 不一定表示业务成功。

服务端返回的 `plannedWorkMinutes/startWindow/endWindow` 是派生预览，客户端提交这些字段不会决定预览结果或数据库字段。规则状态、版本、分钟数、时间、星期和值之间的关系均有校验。

后端沿用 `AttRuleController → IAttRuleService / AttRuleServiceImpl → AttRuleMapper / XML`，显式 `resultMap`，事务、数据范围、操作日志和异常处理复用若依。新增、编辑和删除与场所删除共用场所行锁，并通过唯一索引与版本条件防止竞争。前端位于 `src/views/attendance/rule/index.vue`，API 位于 `src/api/attendance/rule.js`，没有新增前端依赖。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./test/verify-rule.ps1
```
