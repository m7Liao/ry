# 动态二维码与 H5 签到使用说明

更新日期：2026-10-26。本文对应当前源码、本机增量迁移和已通过的接口验证。

## 1. 本阶段交付

在原有办公场所、员工档案与绑定上，新增“签到场次与二维码”“签到记录”管理页面，以及独立 H5 登录、确认签到、本人记录页面。

```text
部门和系统账号 → 办公场所 → 员工档案绑定
                              ↓
管理员创建签到场次 → 展示动态二维码 → 员工扫码登录本人账号
                              ↓
                    核对姓名、工号和场所 → 确认签到
                              ↓
                    保存原始记录 → 管理端 / 本人查询
```

本阶段保存原始签到事实，一场次一人一条。场次不是班次，也不自动区分上班和下班，同一人当天参加不同场次可以分别签到。后续接入的 [每日考勤](每日考勤使用说明.md) 可手动匹配记录并计算异常与工时，[考勤看板](考勤看板使用说明.md) 可聚合查询；没有补签和自动日结。二维码不证明员工实际在场，截图在有效期内可能转发，后续定位或人脸核验需要另行实现。

## 2. 安装与本机启动

本机已经执行 [attendance-checkin.sql](../Vue-springboot3/sql/attendance-checkin.sql)，日常直接启动即可：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./start-dev.ps1
```

访问 `http://localhost`，登录后进入“考勤管理”。如果原会话没有新菜单，退出后重新登录。

其他已安装办公场所与员工模块的数据库，仅执行新增的 `attendance-checkin.sql`。它以 `attendance-base.sql` 为前提，新建两张表和权限菜单，不清空业务记录，可重复执行；已有同名表的结构变更不由 `CREATE TABLE IF NOT EXISTS` 自动完成。

空库初始化顺序：

```sql
USE `ry-vue`;
SOURCE ry_20260417.sql;
SOURCE quartz.sql;
SOURCE attendance-base.sql;
SOURCE attendance-checkin.sql;
SOURCE attendance-rule.sql;
SOURCE attendance-daily.sql;
SOURCE attendance-dashboard.sql;
```

这些脚本位于 `Vue-springboot3/sql/`。前两份会删除重建系统或调度表，不能用于日常升级。规则、每日结果、看板为后来加入的增量；完整初始化共37张表，其中6张考勤业务表，看板仅新增菜单。迁移不创建真实员工和场所。

修改 Java 后，停止服务并重新构建启动：

```powershell
./stop-dev.ps1
./start-dev.ps1 -Build
```

## 3. 角色与准备工作

先按 [基础数据说明](办公场所与员工档案使用说明.md) 创建部门、系统账号、启用场所和在职员工档案。每个参加签到的账号必须有档案，并绑定该二维码对应场所。

迁移只为管理员角色加入新权限，普通员工不会自动获得权限。在“系统管理 → 角色管理”设置：

| 人员 | 建议授权 |
|---|---|
| 场所管理员 | 考勤管理、签到场次与二维码及其需要的详情、创建、关闭、展示二维码；需要查询记录时授予签到记录与详情 |
| 员工 | “考勤管理”下的“移动扫码签到”，权限标识 `attendance:checkin:submit` |
| 查询人员 | 签到记录列表与详情，并配置允许的部门数据范围 |

员工的 H5 页面使用固定路由，不依赖后台菜单页面。无需把场次管理和全体记录查询授权给普通员工。角色变更后重新登录验证。

| 权限 | 用途 |
|---|---|
| `attendance:session:list` | 场次列表 |
| `attendance:session:query` | 场次详情 |
| `attendance:session:add` | 创建立即开始的场次 |
| `attendance:session:edit` | 关闭场次 |
| `attendance:session:qrcode` | 读取场次并签发动态二维码凭证 |
| `attendance:record:list` | 管理端记录列表 |
| `attendance:record:query` | 管理端记录详情 |
| `attendance:checkin:submit` | H5 本人资料、预览、提交、本人记录 |

管理端场次按创建时场所管理部门快照应用若依部门数据范围；管理端记录按签到时员工部门快照应用数据范围，“仅本人”按记录中的账号ID过滤。部门或场所后续调整不会改写历史归属。仅本人数据范围不能管理没有“本人”字段的场次。H5 本人记录始终以当前登录账号过滤，客户端传入其他账号ID无效。

## 4. 管理员创建场次与展示二维码

1. 进入“考勤管理 → 签到场次与二维码”，也可从办公场所列表点击“签到场次”。
2. 点击“创建签到场次”，选择启用且有管理权限的场所，填写名称和开放时长。
3. 时长为5～1440分钟，默认30分钟，保存后立即开始。当前不支持预约开始、修改或重新打开场次。
4. 点击“展示二维码”，保持窗口打开。二维码到期前约10秒自动刷新，也可手动刷新。
5. 本机演示可点击“本机打开签到页”；实际手机扫码先按下一节配置访问地址。
6. 点击该行“记录”，可筛选本场次的签到记录。场次列表的签到人数在重新查询后更新，不是实时推送。
7. 需要提前结束时点击“关闭”。关闭不可撤销，此前签发但尚未到期的凭证也不能再提交。

列表“开放”筛选包含时间已到期但未手动关闭的场次，状态列会显示“进行中 / 已到期 / 已关闭”。到期状态按服务器时间在查询时计算。

## 5. 手机访问方式

默认开发服务只监听本机回环地址，手机不能使用二维码里的 `localhost` 访问电脑。让电脑与手机处于同一局域网，在项目根目录执行：

```powershell
./stop-dev.ps1
./start-dev.ps1 -Lan
```

`-Lan` 将 Vite 前端监听地址改为 `0.0.0.0`。后端仍通过前端 `/dev-api` 代理访问，手机无需直接访问 MySQL、Redis或后端接口。

用 `ipconfig` 找到电脑当前局域网 IPv4 地址，在手机浏览器确认能打开 `http://电脑IP`；若前端实际使用其他端口，附上端口。然后在二维码窗口“手机访问的前端地址”填写该地址，例如 `http://192.168.1.20`。示例IP需替换为实际地址，不能填 `0.0.0.0`。网络、防火墙需要允许手机到前端端口的连接。

地址只接受 HTTP/HTTPS 的站点根地址，不含账号、路径、查询或片段。配置保存于当前浏览器 `localStorage` 的 `attendance.h5Base`，也可用前端环境变量 `VITE_APP_H5_BASE_URL` 指定初始值。仅修改地址不会自动启动监听或配置防火墙。

此阶段没有相机采集和浏览器定位调用；后续接入这些能力时需要单独规划 HTTPS、设备授权与失败处理。当前验证不包含真实手机、微信内置浏览器和外网部署验收。

## 6. 员工签到与本人记录

H5 入口为 `/h5/checkin`，本人记录为 `/h5/records`，独立登录页为 `/h5/login`。

1. 用手机相机或扫码工具识别管理端展示的二维码，在浏览器打开链接。
2. 未登录时进入独立登录页，输入系统账号、密码和验证码；数学验证码填写计算结果。
3. 登录后回到原签到链接。核对姓名、工号和办公场所，点击“确认签到”。
4. 成功页面显示记录编号、服务器签到时间和场所。
5. 点击“查看我的签到记录”，可分页查看本账号历史记录。

打开签到页不会自动打卡，必须确认提交。二维码凭证默认只有60秒有效期，登录耗时过长可能需要重新扫码。已签到用户在有效凭证与开放场次内再次提交，返回原记录，页面显示“本场次已签到”；不会变成另一条记录。场次或凭证已失效时，请从本人记录确认先前结果。

如当前登录账号不是本人，可点击“切换账号”，退出后重新登录。登录恢复只允许返回同站点签到页和本人记录页，不接受任意外部跳转地址。后台与 H5 复用同一个 JWT 登录体系；同浏览器切换账号也会改变后台会话。

## 7. 凭证、身份与记录规则

| 项目 | 当前规则 |
|---|---|
| QR 内容 | H5 URL 与64位十六进制随机 ticket；不包含姓名、密码、JWT 或可自选的员工ID |
| 服务端保存 | Redis 保存 ticket 的 SHA-256 摘要键与场次、到期时间；不在数据库保存原始 ticket |
| 有效期 | `attendance.qr.valid-seconds`，默认60秒，允许10～120秒，不能超过场次结束时间 |
| 多人使用 | 同一有效二维码允许多名绑定该场所的员工各签到一次，不做全局一次性消费 |
| 刷新 | 新旧凭证各有有效期；刷新不会立刻注销尚有效的旧凭证 |
| 重复控制 | 数据库唯一键 `(session_id, employee_id)`，事务与行锁保护并发，重复返回原记录 |
| 身份与时间 | 员工、账号、部门、场所和时间均从登录身份与服务端数据取得，忽略客户端冒填身份和时间 |
| 即时校验 | 提交时重新检查账号、员工在职状态、入职日期、员工部门、场所启用状态、绑定关系、场次及 ticket 有效期 |
| 历史保存 | 保存签到时的工号、姓名、账号名、部门名、场所名和场次名快照；资料改名不改历史 |
| 删除保护 | 有场次的场所不能删除；有记录的员工不能删除。原有账号和部门引用保护继续生效 |
| 数据维护 | 管理端仅查阅原始记录，不提供修改、删除、补签。未来异常更正需另设有审计的业务 |
| 时间显示 | 服务器生成时间，接口格式为 `yyyy-MM-dd HH:mm:ss`，按 GMT+8 显示；本机数据源使用 Asia/Shanghai |

Redis 不可用时不会绕过二维码校验。Redis 重启且未持久化时，已展示凭证失效，需要重新生成；已提交到 MySQL 的记录保留。原始签到不能直接等同于出勤、在岗或工时。

## 8. 架构与接口索引

沿用单体后端和前后端分离架构，没有新增独立认证服务或微服务。后台页面沿用若依 `app-container`、Element Plus 表单和表格、分页、权限指令与 Axios；H5 使用独立移动布局和相同登录接口。

```text
ruoyi-attendance/
├─ controller/           场所、员工、场次、记录、本人签到接口
├─ domain/               实体，以及 dto/请求、vo/返回对象
├─ service/IAtt*.java    业务接口
├─ service/impl/         业务、事务和数据范围实现
├─ mapper/              按业务拆分的 MyBatis 接口
├─ support/AttTicketStore.java  Redis 凭证签发与校验
└─ resources/mapper/attendance/ 按业务拆分的 SQL XML
```

原场所与员工的集中式 `AttService`、`AttMapper` 已拆为各自接口、实现和 Mapper，保留原有校验、绑定及数据权限。项目未启用 MyBatis 全局下划线自动映射，XML 使用显式 `resultMap`。

| 表 | 用途 |
|---|---|
| `att_site` | 场所与管理部门、手工坐标 |
| `att_employee` | 员工档案、系统账号关联、主要场所绑定 |
| `att_checkin_session` | 某个场所的一段签到开放窗口 |
| `att_checkin_record` | 一名员工在一个场次的原始签到记录 |

以下为后端原始路径，开发时由前端添加 `/dev-api` 前缀，需 Bearer Token：

| 方法与路径 | 用途 |
|---|---|
| `GET /attendance/session/list` | 场次分页；`pageNum/pageSize/title/siteId/status` |
| `GET /attendance/session/{id}` | 有数据权限的场次详情 |
| `POST /attendance/session` | 创建；`siteId/title/durationMinutes` |
| `PUT /attendance/session/{id}/close` | 手动关闭 |
| `POST /attendance/session/{id}/qrcode` | 签发；返回 `ticket/expiresAt/serverTime` 等，时间戳为毫秒 |
| `GET /attendance/record/list` | 管理查询；`sessionId/siteId/employeeNo/employeeName/beginDate/endDate/pageNum/pageSize` |
| `GET /attendance/record/{id}` | 有数据权限的记录详情 |
| `GET /attendance/checkin/me` | 本账号最小员工资料，不返回联系方式与系统用户对象 |
| `POST /attendance/checkin/preview` | 提交 `{ "ticket": "..." }` 核对签到信息 |
| `POST /attendance/checkin/submit` | 同上，提交并返回记录与 `repeated` 标记 |
| `GET /attendance/checkin/records` | 本账号分页记录，始终强制限制当前用户 |

列表使用若依 `rows/total/code/msg`，其他接口使用 `data/code/msg`。不能仅看 HTTP 200 判断业务成功，业务码通常为200、401、403、500。日期必须为有效 `yyyy-MM-dd`，结束日期包含当天，开始日期不能晚于结束日期。签发接口按IP每60秒最多60次；预览、提交各按IP每60秒最多300次，实际集中扫码规模增大时需按部署环境调整。

前端页面：`src/views/attendance/session/`、`record/`、`mobile/`；接口：`src/api/attendance/checkin.js`；固定路由与登录恢复：`src/router/index.js`、`src/permission.js`、`src/utils/h5.js`。二维码图片由已锁定依赖的 `qrcode` 生成。

## 9. 验证与复测

已通过 Maven 后端打包、Vite 生产构建和原办公场所 / 员工专项回归。新增 [verify-checkin.ps1](../test/verify-checkin.ps1) 在本机 MySQL、Redis、运行中的真实后端和 Vite 服务验证：

- 身份认证、未授权拒绝、未绑定档案和场所不匹配。
- 真实 Redis TTL、随机凭证、过期 / 伪造凭证、已关闭 / 已到期场次。
- 同码多人签到、二维码刷新后仍按场次去重、两个并发请求仅保存一条。
- 冒填账号 / 员工 / 场所 / 时间无效，员工与管理端分页和部门数据隔离。
- 员工离职、账号禁用、场所停用后的即时提交拒绝。
- 快照不随改名变化、历史删除保护、日期校验、Vue 页面服务端编译。

先启动本地开发服务，再从项目根目录运行：

```powershell
./verify-dev.ps1
./test/verify-attendance.ps1
$env:ATTENDANCE_TEST_MYSQL_PASSWORD = Read-Host '本地测试库 MySQL root 密码'
try {
    powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./test/verify-checkin.ps1
} finally {
    Remove-Item Env:ATTENDANCE_TEST_MYSQL_PASSWORD
}
```

脚本支持 `-BaseUrl`、`-AdminUser`、`-AdminPassword`、`-RedisCli`、`-MySqlCli`。数据库清理固定面向本机 `ry-vue`，只处理本次随机前缀和已创建ID的签到测试记录、场次及基础数据；会留下正常登录与操作审计。限当前本地开发库使用。清理失败会报告测试前缀，需核对处理。

接口回归和构建不等于真实手机验收。实际演示前还应检查局域网访问、手机扫码识别、登录耗时、页面操作及不同设备浏览器表现。
