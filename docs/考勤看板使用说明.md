# 基础考勤看板使用说明

更新日期：2026-10-27。数据来源为当前 `att_daily_result`，不新增业务表。

## 1. 入口与操作

登录后进入“考勤管理 → 考勤看板”，工作台也有“打开考勤看板”入口。新菜单未出现时退出后重新登录。

1. 选择“近7天”“近30天”，或自选不超过31天的日期范围。
2. 按需选择办公场所，点击“查询”。默认统计上海时区最近7天，含当天。
3. 查看五项统计、每日趋势、已结算异常分布、场所对比和明细表。
4. 有每日结果列表权限时，可点击卡片、图表数据点或场所表中的数值进入对应明细。
5. 计算或重算每日结果后，返回看板会重新查询，也可主动点击“查询”刷新。

看板不自动创建每日结果，不进行定时轮询。若无数据，先由有权限的管理人员在每日考勤结果中执行计算。查询失败时提示错误，已有数据标明为上次成功查询的结果。

## 2. 统计口径

**多日期累计按人次统计，一名员工同一天最多一人次。** 同一员工连续出勤7天可以产生7人次，不能把这个总数当作7名员工。页头“覆盖员工”单独按员工ID去重，覆盖范围包括已生成的正常、异常、待结算和休息日结果。

| 统计项 | 定义 |
|---|---|
| 已结算 | `NORMAL` 与 `ABNORMAL` 结果人次之和 |
| 正常 | 状态为 `NORMAL` |
| 异常 | 状态为 `ABNORMAL`；同一天多种异常仍只计一次 |
| 缺卡 | 已结算结果中上班或下班任一缺卡，双缺卡也只计一次 |
| 待结算 | 状态为 `PENDING`，单独展示，不并入已结算 |
| 休息日 | 状态为 `REST`，页头、趋势和场所明细单独展示 |
| 已生成结果 | 四类状态的结果总数；不代表应出勤总人数 |
| 最近计算 | 当前筛选和权限范围内结果的最大计算时间，不是看板查询时间 |

满足以下关系：

```text
已结算 = 正常 + 异常
已生成 = 已结算 + 待结算 + 休息日
```

缺卡是已结算异常中的一个子集，不能再与异常相加。迟到、早退、上班缺卡、下班缺卡是四个可重叠的类型，类型分布只统计已结算结果。例如同一天迟到又早退，异常卡片计1，两个类型各计1。

待结算结果可能已有临时迟到或上班缺卡标记，这些临时标记不会混入已结算异常分布。没有计算的人员、日期不会被补成缺勤，也不据此计算出勤率或缺勤率。

## 3. 图表与场所展示

- 每日趋势包含正常、异常、待结算和休息日，休息日系列默认隐藏，可通过图例开启。
- 日期区间内没有结果的日期补0，表示可见结果数为0，不代表当日无人出勤或全员缺勤。
- 已结算异常分布使用条形图，避免把重叠类型当作互斥比例。
- 场所图按已生成结果人次排序，展示前10个场所；完整场所数据保留在下方分页表中。
- 场所始终按ID分组，改名不会分成两个场所。展示名称采用统计期内最近创建结果保存的名称快照，不额外读取范围外的场所资料。
- 场所选项来自当前日期内有权限的每日结果，不按场所管理部门另行缩窄。员工部门与场所管理部门不同时，仍可筛选本人有权查看的结果。

图表复用项目已有 ECharts，未增加依赖。容器大小改变时自动调整，页面缓存停用时释放图表并清除旧统计，重新进入后查询最新数据。无结果时展示0、空态或零值曲线，不添加演示数字。

## 4. 点击查看明细

| 点击内容 | 传入每日列表的条件 |
|---|---|
| 已结算卡片 | `resultGroup=SETTLED` |
| 正常 / 异常 / 待结算 | 对应 `resultStatus` |
| 缺卡卡片 | `resultGroup=MISSING`，后端同时限制已结算和任一缺卡 |
| 趋势数据点 | 该天的日期范围和对应状态 |
| 异常类型条形 | `resultGroup=SETTLED` 加对应 `abnormalType` |
| 场所图数据段 | 原日期范围、该场所ID及对应状态 |
| 场所表数值 | 原日期范围、该场所及对应卡片条件 |

每日列表增加可见的“统计范围”筛选：已结算、已结算缺卡。进入缓存中的旧列表时会重新读取本次路由，清除上次姓名、工号、状态及异常筛选，避免条件串用。常规列表“异常类型”仍可查询待结算中的临时标记；从看板跳转时附带已结算条件。

## 5. 权限与数据范围

看板页面与统计接口使用 `attendance:dashboard:view`。迁移仅授予管理员角色，普通角色需管理员手动授权。

只有看板权限的账号可以查看聚合数据，不会因此取得员工档案、原始签到、每日结果列表或详情权限。未授予 `attendance:daily:list` 时，卡片和图表不执行明细跳转；直接请求每日列表仍被后端拒绝。

统计直接按每日结果中保存的员工部门快照应用若依数据范围，支持本部门、自定义部门、本部门及以下、全部和仅本人。汇总、趋势、场所对比及场所选项统一过滤；客户端传入 `params[dataScope]` 不能扩大范围。

需要查看明细时，建议同一考勤角色同时授予看板和每日列表权限，使用一致的数据范围。明细接口会独立执行其权限与范围检查；若不同角色为两个权限配置了不同范围，统计与明细的可见范围也可能不同。

## 6. 安装与接口

本机已执行 [attendance-dashboard.sql](../Vue-springboot3/sql/attendance-dashboard.sql)。已有每日考勤模块的库仅执行本文件，它只补充菜单和管理员角色关联，可重复执行，不新增表，不清空结果。业务表总数仍为37张，其中6张考勤表。

空库在系统、Quartz、基础数据、扫码、规则、每日结果脚本之后，再执行：

```sql
SOURCE attendance-dashboard.sql;
```

后端沿用 Controller → Service接口 / Impl → Mapper / XML：

```text
AttDashboardController
    → IAttDashboardService / AttDashboardServiceImpl
        → AttDashboardMapper / AttDashboardMapper.xml
```

接口为 `GET /attendance/dashboard`，开发时使用 `/dev-api/attendance/dashboard`，需原有 Bearer JWT。

| 参数 | 说明 |
|---|---|
| `beginDate`、`endDate` | 有效 `yyyy-MM-dd`，必须同时提供；均省略时默认最近7天 |
| `siteId` | 可选，正整数场所ID |

范围包含首尾日期，开始不晚于结束，不接受未来日期，每次最多31天。未知或无可见结果的场所返回零统计，不泄露其他范围的数据。

业务成功返回 `code=200`，`data` 包括：

| 字段 | 用途 |
|---|---|
| `beginDate/endDate/siteId` | 本次实际统计条件 |
| `summary` | 总体人次、去重员工数、异常类型与最近计算时间 |
| `trend` | 按日期排列，补齐零值日期 |
| `sites` | 当前场所筛选下的场所分组，按结果数排序 |
| `siteOptions` | 当前日期范围内全部可见场所的ID与显示名，选择单个场所后仍保留其他可选项 |

三个聚合 SQL 在只读、可重复读事务中执行，保证一次返回的统计视图一致；不拉取全部员工明细再在前端计算，不缓存不同角色的聚合结果。前端路径为 `src/views/attendance/dashboard/`，请求封装为 `src/api/attendance/dashboard.js`，路由条件工具为 `src/utils/attendanceDashboard.js`。

## 8. 当前边界

本版为每日结果的统计看板，没有实时在岗定位、未计算人员缺勤推断、预测、工时薪资核算或自动日结。后续自动日结应复用每日计算逻辑，明确系统任务执行范围、跨天窗口结束时刻、失败重试和幂等，不能用看板刷新代替业务结算。
